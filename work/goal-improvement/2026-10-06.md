## Product brief

Documented purpose: discover Finnish-language/tagged live streams, examine channel/broadcast audience and captured chat activity, explore aggregate channel communities, and manage one's own data. The repository has public/private analytics boundaries and an administrator ingestion console. Preserve those boundaries and observation caveats.

Working audience hypothesis: Finnish Twitch viewers and broadcasters returning to find a channel or understand a broadcast moment. They need to know what is current, compare recorded periods, follow details and return without rebuilding their context. No interviews, usage analytics or demand evidence are claimed.

## Research and selected direction

Accessed 2026-10-06. Observations below are public-page/document evidence, not invented user research.

- [TwitchTracker rankings](https://twitchtracker.com/channels/ranking): visible table labels distinguish average audience, hours streamed and all-time peak; the ranking's 30-day scope is stated above it. Adopt explicit scope/denominators beside numbers; do not imply all samples are current.
- [SullyGnome channel statistics](https://sullygnome.com/channel/effect/365): indexed first-party page exposes a selected period and game airtime. Direct fetch of the example Myth channel returned 403; no interaction claim. Preserve task-specific time scope and observed-airtime meanings already implemented.
- [Streams Charts API](https://streamscharts.com/api/docs/): first-party documentation describes separate broadcast, current-live and chat-engagement datasets. The public overview could not be fetched. Its scale/features do not justify adding paid-suite complexity here; separate captured chat from live audience.
- [Grafana share documentation](https://grafana.com/docs/grafana/latest/visualizations/dashboards/share-dashboards-panels/): documented direct links can lock a relative time range to an absolute one. Continue to preserve analytical context through refresh and navigation; revisit the return journey after this batch.
- [Next caching guide](https://nextjs.org/docs/app/guides/caching-without-cache-components): time-based revalidation returns stale data to the first request and updates in the background. This explains the live observation: first homepage had 270 sessions from ~10h earlier, direct API and the subsequent homepage had 69 with current observations. All eleven production worker loops were fresh; discovery HTTP status 200. No ingestion/process repair is indicated.

Design decision (Operate, agent-selected): retain restrained dark/violet operational UI, native search/buttons, tabular counts and dense comparison rows. Domain: sessions, audience snapshots, Finnish language/tag eligibility, chat coverage, observation gaps, channels and broadcast moments. Palette: existing near-black surfaces, violet actions, green recent observations, amber uncertainty, muted timestamp text. Signature: viewer evidence and chat coverage stay separate beside the broadcast identity. Avoid decorative dashboard cards, a blanket green "live" claim, and hover-only freshness explanations.

Component intent: a returning viewer must know whether a status can still be trusted, inspect old evidence and refresh without losing search. Hierarchy: status meaning and refresh beside the timestamp, comparable counts with sample denominators, then streams. Reuse current panels/pills/buttons; 4px spacing rhythm, compact 16px notice padding, system sans with existing weight hierarchy and tabular numerals. No new motion, identity, renderer or dependencies.

Acceptance refinement from code: known Finnish-tagged channel discovery runs every **15 minutes**, so recent status uses **30 minutes** (two normal scan intervals), not the initial ten-minute hypothesis. Older open sessions are *unconfirmed*, never automatically ended. Viewer totals include recent samples only, preserve zero and show missing as a dash. Current-status views fetch without stale-while-revalidation; historical/raw detail caches retain their existing budget. Header explicitly calls this a loaded snapshot. This is freshness presentation, not an uptime guarantee.
